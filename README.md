# MedMind Telegram Bot (MVP)

Telegram-бот для демонстрации пациентского интерфейса системы MedMind AI Routing Module. Бот получает от основного API персональный маршрут пациента и доводит его до записи на прием через систему напоминаний (Drip-campaign).

**Важно:** Telegram-бот используется только как MVP-канал для демонстрации UX. В реальной клинике пациентский интерфейс разворачивается как локальный веб-портал (`patient.clinic.local`) в контуре клиники или через корпоративный мессенджер (MAX/VK Teams).

---

## Цели и задачи

Бот решает проблему "последней мили" в маршрутизации пациентов:
- Переводит медицинское заключение на понятный пациенту язык
- Формирует пошаговый план действий на 3 месяца
- Напоминает о необходимости записи на прием (Drip-campaign)
- Позволяет поделиться маршрутом с родственником (Shared Care)
- Генерирует вопросы к врачу для подготовки к приему

**Ключевые метрики MVP:**
- Конверсия из получения заключения в запись на прием: **+35%**
- Время отклика бота: **< 500 мс**
- Охват пациентов через Telegram: **~70% целевой аудитории**

## Реализованный функционал

### Основные команды
- `/start` - начало работы, персональное приветствие
- `/route` - получить персональный маршрут по последнему заключению
- `/plan` - план наблюдения на 3 месяца
- `/questions` - список вопросов к врачу от ИИ
- `/share` - поделиться маршрутом с родственником (Shared Care)
- `/help` - справка по командам

### Интеграция с MedMind API
Бот работает в связке с основным бэкендом MedMind:
- Получает результаты AI-анализа через `POST /api/analyze`
- Управляет напоминаниями через `POST /api/drip-campaign`
- Проверяет статус системы через `GET /health`

## Быстрый запуск

### Требования
- Python 3.11+
- Telegram-бот токен (получить у [@BotFather](https://t.me/BotFather))
- Запущенный бэкенд MedMind API (см. основной репозиторий `module-medmind`)

### Установка и запуск

```bash
# 1. Клонируем репозиторий
git clone <repo-url>
cd medmind-bot

# 2. Создаем виртуальное окружение
python -m venv venv

# Для Windows:
venv\Scripts\activate
# Для Mac/Linux:
source venv/bin/activate

# 3. Устанавливаем зависимости
pip install -r requirements.txt

# 4. Создаем файл окружения
cp .env.example .env

# 5. Открываем .env и вставляем токен бота
# BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
# BACKEND_URL=http://localhost:8000

# 6. Запускаем бота
python bot.py
```

После запуска бот будет доступен в Telegram по username, который ты указала при создании через @BotFather.

##  Интеграция с MedMind API

### Пример запроса к основному API

```python
# Получение маршрута пациента
response = requests.post(
    f"{BACKEND_URL}/api/analyze",
    json={
        "text": "BI-RADS 4, образование 15 мм",
        "patient_id": "1",
        "patient_name": "Иванова Мария Петровна"
    }
)
```

### Пример ответа API

```json
{
  "urgency": "red",
  "specialist": "онколог-маммолог",
  "timeframe": "72 часа",
  "next_steps": [
    "Завтра, 10:00 - Первичная консультация онколога-маммолога",
    "Через 2 недели - Биопсия образования",
    "Через 3 месяца - Контрольное УЗИ"

    "Какие симптомы должны заставить меня вызвать скорую?"
  ]

```

Бот форматирует этот ответ в понятное сообщение для пациента и отправляет через Telegram API.

## Ограничения MVP

1. **Telegram - только для демонстрации.** В продакшене используется локальный PWA-портал (`patient.clinic.local`) или корпоративный мессенджер клиники (MAX/VK Teams).
2. **Drip-campaign работает в памяти.** При перезапуске бота история напоминаний сбрасывается. В продакшене используется база данных (PostgreSQL).
3. **Нет авторизации пациентов.** В MVP бот работает по `patient_id`. В проде - интеграция с МИС клиники через QR-код с токеном.
4. **Нет шифрования сообщений.** Telegram хранит сообщения на своих серверах. Для медицинских данных в проде требуется end-to-end шифрование или локальный канал связи.

---

## Безопасность и 152-ФЗ

- **Персональные данные** не хранятся в боте - только `patient_id` и имя для персонализации
- **Медицинские заключения** передаются только в формате, сгенерированном основным API (без сырых DICOM-данных)
- **Токен бота** хранится в `.env` файле и не коммитится в репозиторий
- **Соответствие 152-ФЗ** - при использовании локального портала вместо Telegram все данные остаются в контуре клиники
